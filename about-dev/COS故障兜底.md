# COS 故障兜底维护说明

## 行为

正常写入直接使用 COS；仅 COS SDK 或网络异常时保存本地完整文件和数据库待办。普通本地模式不启用同步。不下载历史图库，无本地副本时远端故障返回 503，处理任务保留存储不可用原因。

## 代码入口

- [组合存储](../backend/app/storage/fallback.py)：写入、读取、待办及单对象同步。
- [对象锁](../backend/app/storage/object_lock.py)：共享目录文件锁，Linux 使用 flock，Windows 使用字节锁；支持同线程重入，进程退出自动释放。锁文件不能删除。
- [待办模型](../backend/app/models/storage_pending.py)与[迁移](../backend/migrations/versions/0010_storage_pending.py)：对象路径哈希为主键，避免 MySQL 长路径索引限制。
- [独立扫描入口](../backend/app/storage/sync.py)：每轮最多 50 项，轮间等待 60 秒，以主键游标继续扫描，单对象失败不退出服务。
- [上传及删除](../backend/app/api/routes/images.py)、[图片处理](../backend/worker/tasks/image_tasks.py)、[文件响应](../backend/app/services/image_file_response.py)、[公开接口](../backend/app/api/routes/public_images.py)。MCP 链接和处理调用复用这些链路。

## 文件与事务

共享图片目录下的 .cos-fallback 子目录保存对象副本和锁。副本使用对象哈希及修订号命名，先写临时文件再原子发布；数据库待办提交后才能返回保存成功。SDK 写入失败后恢复输入流位置，再完整保存。

上传持有原图对象锁直到记录提交。数据库唯一约束保留；失败清理只处理本次保存且未被引用的对象。处理任务持有原图锁，生成和提交版本时同时持有版本对象锁。删除先持有原图锁，再读取最新版本列表；图片删除和待删除操作同事务提交。过期版本同样事务登记待删除。

同步只上传已由图片或版本引用的待上传对象。补传使用原路径，上传和存在性确认成功后先提交“待清理”状态，再删除本地文件、完成待办。因此在删除文件前后退出都可继续。删除操作取消上传，后台删除远端；重新上传生成新修订，旧扫描快照不能清理新副本。

未提交引用的待上传对象不会自动补传；同名重试可以替换它。未提交事务、磁盘或数据库错误不伪装成功。进程在文件发布但待办提交前异常退出可能留下未引用文件，当前不实现自动孤儿文件回收。

本地读取在对象锁内复制到独立临时流，再释放锁供响应使用；补传清理不会中断正在读取的响应。不同对象不共用全局锁。同步运行于独立进程，不占 Celery 执行槽；同对象操作可能等待该对象当前请求完成。COS 请求超时 10 秒，关闭 SDK 自动重试。

COS 对象已同步且没有待办副本时，原图、处理图和历史版本接口返回短期 COS 签名跳转地址，图片正文不再经过 API；本地待上传对象仍由 API 流式返回。应用稳定链接不会变，外部客户端需要跟随 HTTP 跳转。前端脚本下载还需要在 COS 桶中允许实际前端来源的跨域 GET/HEAD 请求，并允许浏览器预检所需请求头，不使用凭据跨域。签名地址有效期为 1 小时，响应中的文件名、媒体类型和缓存策略由应用生成。

## 部署约束

API、图片 Worker、同步服务必须使用同一数据库和同一个支持文件锁的共享本地挂载。当前方案针对单宿主机多容器/多进程，不覆盖跨主机独立磁盘。共享目录不能在待办清空前清理或更换。COS 桶还必须配置前端实际来源的跨域规则，否则脚本下载和预览可能被浏览器拦截。部署操作见[部署说明](../deploy/README.md)。

- 专项模拟故障回归 8 项通过：正常直写、存在性检查失败、流读取后写入失败、真实图片处理、下载/公开链接/版本/缩略图、恢复补传清理、重建实例、未提交引用、旧修订、重复与并发上传、大小写唯一约束、同步删除竞争、跨进程锁释放、迁移升级/降级。
- 相关既有处理、迁移、服务和集成令牌/上传客户端测试 39 项通过。
- 全量单进程测试首轮 40 通过、22 失败，涉及 MCP 会话管理器重复启动及旧 MCP 测试未初始化配置；未为此修改无关业务代码。
- API 用例逐条独立进程执行为 20/22 通过；剩余一项在测试内部重复启动 MCP，另一项要求清理旧本地处理临时文件。未修改本地存储行为。
- 新增存储模块、模型和迁移的 Ruff 检查通过；差异空白检查通过，Compose 静默配置校验无错误输出。
- 专项测试通过后已用专用编辑工具清空临时回归文件，因当前工具没有删除文件接口，保留空文件；现有后端测试未删除。
- 真实 COS、MySQL 并发、Linux 文件锁、容器重启和线上部署尚未执行；模拟测试不等同线上验收。
