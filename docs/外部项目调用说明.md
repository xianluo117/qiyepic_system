# 图片上传与链接调用说明

## 1. 基础地址

将 `BASE_URL` 替换为图床系统实际访问地址。

```text
BASE_URL=http://127.0.0.1:1230
```

接口基础路径为：

```text
BASE_URL/api
```

## 2. 登录获取令牌

上传前必须登录。

### 请求

```http
POST /api/auth/login
Content-Type: application/x-www-form-urlencoded
```

表单参数：

| 参数 | 必填 | 说明 |
|---|---|---|
| `username` | 是 | 系统账号 |
| `password` | 是 | 系统密码 |

示例：

```text
POST {BASE_URL}/api/auth/login
Content-Type: application/x-www-form-urlencoded

username=your_username&password=your_password
```

成功响应：

```json
{
  "access_token": "登录令牌",
  "token_type": "bearer"
}
```

保存 `access_token`，上传时放入请求头：

```http
Authorization: Bearer 登录令牌
```

## 3. 上传图片

### 请求

```http
POST /api/images/upload
Authorization: Bearer 登录令牌
Content-Type: multipart/form-data
```

表单参数：

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `files` | 文件 | 是 | 图片文件；多个文件重复提交该字段 |
| `sku` | 字符串 | 是 | 货号 |
| `ratio_width` | 整数 | 是 | 目标比例宽度，例如 `3` |
| `ratio_height` | 整数 | 是 | 目标比例高度，例如 `4` |
| `min_short_side_px` | 整数 | 是 | 处理图最小短边，例如 `1500` |

支持格式：JPEG、PNG、WebP。

单个文件默认不能超过 30 MB。

示例：

```text
POST {BASE_URL}/api/images/upload
Authorization: Bearer 登录令牌
Content-Type: multipart/form-data

files=@D:/images/product.jpg
sku=ABC123
ratio_width=3
ratio_height=4
min_short_side_px=1500
```

上传多个文件时，重复提交 `files` 字段：

```text
files=@D:/images/product-1.jpg
files=@D:/images/product-2.png
files=@D:/images/product-3.webp
sku=ABC123
ratio_width=3
ratio_height=4
min_short_side_px=1500
```

## 4. 上传响应

```json
{
  "results": [
    {
      "filename": "product.jpg",
      "success": true,
      "image": {
        "id": 123,
        "employee_id": "E001",
        "sku": "ABC123",
        "original_filename": "product.jpg",
        "status": "pending",
        "current_revision": null
      },
      "error": null
    }
  ]
}
```

每个文件单独返回结果：

- `success=true`：上传成功；
- `success=false`：上传失败，错误原因在 `error`；
- `image.id`：后续查询处理状态所需的图片 ID；
- `image.employee_id`：员工 ID，可直接用于拼接图片 URL；
- `image.current_revision`：处理图版本号。刚上传时通常为 `null`，处理完成后才有值。

上传成功后图片会异步处理。上传接口不会等待处理完成，因此不能保证首次响应中已经有 `current_revision`。

## 5. 获取处理版本号

上传成功后，保存响应中的 `image.id`，然后使用该 ID 查询图片处理状态：

```http
GET {BASE_URL}/api/images/{image_id}
Authorization: Bearer 登录令牌
```

建议每隔 1～2 秒查询一次，直到状态发生变化。

处理中的响应示例：

```json
{
  "id": 123,
  "status": "processing",
  "current_revision": null
}
```

处理成功的响应示例：

```json
{
  "id": 123,
  "employee_id": "TEST1",
  "sku": "HB20-DY320-2",
  "original_filename": "yeloow (4).jpg",
  "status": "success",
  "current_revision": "abcd"
}
```

当 `status=success` 且 `current_revision` 不为空时，即可拼接处理图 URL。处理失败时，停止轮询并读取 `error_message`。

## 5. 拼接图片完整 URL

系统前端使用的是**不包含图片 ID 的业务 URL**。URL 由员工编号、货号、文件名和图片类型组成。

路径参数必须进行 URL 编码。例如文件名 `yeloow (4).jpg` 应编码为 `yeloow%20(4)`。

### 5.1 缩略图 URL

缩略图使用图片 ID：

```text
{BASE_URL}/api/public/images/{image_id}/thumbnail
```

### 5.2 原图 URL

原图 URL 不包含图片 ID，`filename` 不包含扩展名：

```text
{BASE_URL}/api/public/images/{employee_id}/{sku}/{filename}/original
```

### 5.3 处理图 URL

处理图 URL 不包含图片 ID，必须带 `rev` 参数：

```text
{BASE_URL}/api/public/images/{employee_id}/{sku}/{filename}/processed?rev={current_revision}
```

示例：

```text
https://qiyeimage.xiaoc-ai.com/api/public/images/TEST1/HB20-DY320-2/yeloow%20(4)/processed?rev=abcd
```

参数来源：

- `employee_id`：上传响应中的 `image.employee_id`；
- `sku`：上传时提交的货号；
- `filename`：`original_filename` 去掉最后一个扩展名后的文件名，并进行 URL 编码；
- `current_revision`：图片处理完成后返回的版本修订号。

同一员工、同一货号下，如果存在多个相同文件名但扩展名不同的图片，不包含 ID 的业务 URL 可能无法唯一定位，接口会返回冲突错误。

## 7. 调用流程

```text
1. 登录，获取 access_token
2. 使用 Bearer Token 上传图片
3. 从响应读取 image.id、employee_id、sku、original_filename
4. 立即拼接缩略图或原图 URL
5. 查询图片状态，等待 status=success
6. 读取 current_revision
7. 拼接处理图 URL
```
