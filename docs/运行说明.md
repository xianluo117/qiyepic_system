# Docker Compose 运行说明

## 1. 部署方式

系统已改为 Docker Compose 部署。服务器不需要单独安装 Python、Node.js、venv、MySQL 或 Redis，只需要：

- Docker Engine；
- Docker Compose 插件；
- 可选的宝塔面板和宝塔 Nginx。

Compose 会启动以下服务：

| 服务     | 作用                                     |
| -------- | ---------------------------------------- |
| `web`    | Nginx 和 Vue 静态前端，对外提供 Web 访问 |
| `api`    | FastAPI 接口服务                         |
| `worker` | Celery 图片处理 Worker                   |
| `mysql`  | MySQL 8.4 数据库                         |
| `redis`  | Redis 7.4 任务队列                       |

`web`、`api` 和 `worker` 使用同一个镜像：

```text
qingmiaoai/qiyeimagesystem
```

## 2. 首次启动

在项目根目录操作。

复制环境变量：

```text
cp .env.example .env
```

必须修改：

```text
SECRET_KEY=至少 32 个字符的随机密钥
MYSQL_PASSWORD=MySQL 应用账号强密码
MYSQL_ROOT_PASSWORD=MySQL root 强密码
BOOTSTRAP_ADMIN_USERNAME=管理员用户名
BOOTSTRAP_ADMIN_PASSWORD=至少 12 位的管理员强密码
```

`.env` 已被 Git 和 Docker 构建上下文忽略，不得提交到仓库。

启动全部服务：

```text
docker compose up -d
```

首次启动会自动：

1. 下载应用、MySQL 和 Redis 镜像；
2. 创建 MySQL 与 Redis 数据卷；
3. 等待 MySQL 可用；
4. 执行 Alembic 数据库迁移；
5. 启动 FastAPI、Celery 和 Nginx；
6. 在管理员不存在时创建初始管理员。

## 3. 访问地址

默认 Web 地址：

```text
http://127.0.0.1:1230
```

通过 Web 容器访问接口文档：

```text
http://127.0.0.1:1230/docs
```

健康检查：

```text
http://127.0.0.1:1230/health
```

FastAPI 不直接暴露到宿主机，只允许 Compose 网络中的 Web 容器访问。

## 4. 常用命令

查看状态：

```text
docker compose ps
```

查看全部日志：

```text
docker compose logs -f
```

查看指定服务日志：

```text
docker compose logs -f api
docker compose logs -f worker
docker compose logs -f mysql
```

重启：

```text
docker compose restart
```

更新到 Docker Hub 最新镜像：

```text
docker compose pull
docker compose up -d
```

停止并删除容器：

```text
docker compose down
```

不得随意执行：

```text
docker compose down -v
```

该命令会删除 MySQL 和 Redis 数据卷。

## 5. 本地构建

需要从当前源码构建镜像时执行：

```text
docker compose build
docker compose up -d
```

或者：

```text
docker compose up -d --build
```

镜像构建过程会安装前端和后端依赖，因此宿主机不需要 Python、Node.js 或 venv。

开发者仍可使用 `backend/requirements-dev.txt` 和 `frontend/package-lock.json` 在宿主机进行测试，但不是生产部署的必需步骤。

## 6. 数据持久化

### 6.1 图片

默认映射到项目根目录：

```text
./data/images
```

Linux 生产服务器建议在 `.env` 中设置绝对路径：

```text
IMAGE_DATA_PATH=/data/image-system
```

目录结构：

```text
员工ID/original/货号/原文件名
员工ID/processed/货号/原文件名
```

### 6.2 数据库和 Redis

MySQL 使用：

```text
qiye-image-system_mysql-data
```

Redis 使用：

```text
qiye-image-system_redis-data
```

可使用以下命令查看：

```text
docker volume ls
```

生产环境必须备份图片目录和 MySQL 数据。

## 7. 宝塔部署

### 7.1 安装环境

在宝塔软件商店安装 Docker 管理器。无需创建 Python 项目，也无需安装 Python 项目管理器。

将仓库放到例如：

```text
/www/wwwroot/qiyepic_system
```

在该目录创建 `.env`，然后启动：

```text
docker compose up -d
```

### 7.2 宝塔网站反向代理

Compose 默认将 Web 服务发布到：

```text
127.0.0.1 或服务器IP:1230
```

在宝塔创建普通 Nginx 网站，将域名反向代理到：

```text
http://127.0.0.1:1230
```

域名 HTTPS 证书继续由宝塔管理。

如果只允许本机宝塔 Nginx 访问，可将 `compose.yaml` 的端口映射改为：

```text
127.0.0.1:1230:80
```

### 7.3 防火墙

使用域名和宝塔 Nginx 代理时，不需要对公网开放 `1230`。只开放：

- 80；
- 443；
- 宝塔管理端口。

MySQL、Redis 和 FastAPI 均未在 Compose 中映射宿主机端口。

## 8. 镜像发布

应用镜像名称：

```text
qingmiaoai/qiyeimagesystem
```

构建：

```text
docker build -t qingmiaoai/qiyeimagesystem:latest .
```

推送：

```text
docker push qingmiaoai/qiyeimagesystem:latest
```

建议正式发布时同时使用版本标签，例如：

```text
docker tag qingmiaoai/qiyeimagesystem:latest qingmiaoai/qiyeimagesystem:0.1.0
docker push qingmiaoai/qiyeimagesystem:0.1.0
```

## 9. 图片清晰度处理

图片短边不足时：

1. 每阶段最多使用 2 倍 Lanczos 插值放大；
2. 最后一阶段精确缩放至目标尺寸；
3. 仅对放大结果应用轻度 `UnsharpMask` 锐化；
4. JPEG 和 WebP 使用 95 质量保存。

锐化参数：

```text
radius=1.2
percent=110
threshold=3
```

该方案用于减少普通插值造成的柔化，不能恢复原图中不存在的真实细节。
