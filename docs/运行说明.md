# Docker Compose 运行说明

## 1. 部署方式

系统已改为 Docker Compose 部署。服务器不需要单独安装 Python、Node.js、venv、MySQL 或 Redis，只需要：

- Docker Engine；
- Docker Compose 插件；
- 可选的宝塔面板和宝塔 Nginx。

Compose 会启动以下服务：

| 服务     | 作用                                     |
| -------- | ---------------------------------------- |
| `web`    | Nginx 和 Vue 静态前端，对外提供 Web 访问 |
| `api`    | FastAPI 接口服务                         |
| `worker` | Celery 图片处理 Worker                   |
| `mysql`  | MySQL 8.4 数据库                         |
| `redis`  | Redis 7.4 任务队列                       |

## 2. 角色入口

- 员工端：`/gallery`，仅显示和管理当前账号上传的图片。
- 管理员后台：`/admin/images`，包含全部图片、账号管理和系统日志。
- 图片处理失败时，图库可直接查看失败原因并重新提交任务。
- 系统日志记录登录、账号管理、图片上传/删除/重试及 Worker 处理结果。

`web`、`api` 和 `worker` 使用同一个镜像：

```text
qingmiaoai/qiyeimagesystem
```

## 3. 首次启动

在项目根目录操作。

复制环境变量：

```text
cp .env.example .env
```

必须修改：

```text
SECRET_KEY=至少 32 个字符的随机密钥
MYSQL_PASSWORD=MySQL 应用账号强密码
MYSQL_ROOT_PASSWORD=MySQL root 强密码
BOOTSTRAP_ADMIN_USERNAME=管理员用户名
BOOTSTRAP_ADMIN_PASSWORD=至少 12 位的管理员强密码
```

`.env` 已被 Git 和 Docker 构建上下文忽略，不得提交到仓库。

启动全部服务：

```text
docker compose up -d
```

首次启动会自动：

1. 下载应用、MySQL 和 Redis 镜像；
2. 创建 MySQL 与 Redis 数据卷；
3. 等待 MySQL 可用；
4. 执行 Alembic 数据库迁移；
5. 启动 FastAPI、Celery 和 Nginx；
6. 在管理员不存在时创建初始管理员。

## 3. 访问地址

默认 Web 地址：

```text
http://127.0.0.1:1230
```

通过 Web 容器访问接口文档：

```text
http://127.0.0.1:1230/docs
```

健康检查：

```text
http://127.0.0.1:1230/health
```

FastAPI 不直接暴露到宿主机，只允许 Compose 网络中的 Web 容器访问。

## 4. 常用命令

查看状态：

```text
docker compose ps
```

查看全部日志：

```text
docker compose logs -f
```

查看指定服务日志：

```text
docker compose logs -f api
docker compose logs -f worker
docker compose logs -f mysql
```

重启：

```text
docker compose restart
```

更新到 Docker Hub 最新镜像：

```text
docker compose pull
docker compose up -d
```

停止并删除容器：

```text
docker compose down
```

不得随意执行：

```text
docker compose down -v
```

该命令会删除 MySQL 和 Redis 数据卷。

## 5. 本地构建

需要从当前源码构建镜像时执行：

```text
docker compose build
docker compose up -d
```

或者：

```text
docker compose up -d --build
```

镜像构建过程会安装前端和后端依赖，因此宿主机不需要 Python、Node.js 或 venv。

开发者仍可使用 `backend/requirements-dev.txt` 和 `frontend/package-lock.json` 在宿主机进行测试，但不是生产部署的必需步骤。

## 6. 腾讯云 COS 存储

默认使用本地存储。如需将原图、处理图和历史版本放入腾讯云 COS，同时继续使用图床 URL 对外提供图片，在 `.env` 中配置：

```text
STORAGE_BACKEND=cos
COS_SECRET_ID=腾讯云 SecretId
COS_SECRET_KEY=腾讯云 SecretKey
COS_REGION=ap-guangzhou
COS_BUCKET=examplebucket-1250000000
```

COS Bucket 建议保持私有。客户端不会直接访问 COS，图片请求仍访问图床 URL，由 API 从 COS 中转返回；缩略图继续缓存于 `IMAGE_DATA_PATH` 下。

切换前，先保持 `STORAGE_BACKEND=local`，暂停上传、重新处理和删除操作，等待 Worker 队列完成，然后在项目根目录执行：

```text
docker compose run --rm --no-deps api python /app/tools/migrate_images_to_cos.py
```

迁移时 COS 中已存在的完整对象键会跳过，不比较或覆盖内容。本地文件也不存在时跳过并在结束时打印缺失清单。最后分别统计成功上传、COS 已存在及缺失数量；查询或上传失败仍直接报错。缺失文件不会自动恢复，不删除数据库记录。此规则仅用于手动迁移，不改变日常上传的同名限制。

迁移结束并确认缺失清单后，将 `.env` 的 `STORAGE_BACKEND` 改为 `cos`，确保 API 和 worker 使用同一套 COS 配置，然后重启服务：

```text
docker compose up -d
```

迁移工具只迁移数据库引用的原图、当前处理图和历史版本，不迁移缩略图和无引用文件。确认 COS 模式运行正常前，不要删除本地图片目录。切换到 COS 后，已有图片的图床 URL 不变。

### 6.1 校验和清理本地副本

仅在 API 和 worker 已切换 COS、历史图片访问正常后执行。暂停上传、重新处理、删除以及其他直接修改本地或 COS 图片的操作，等待活动任务和排队任务全部完成；仅检查 active 为空不能证明队列排空。校验和清理期间保持暂停。

默认只预览：按数据库引用的原图、当前处理图和历史版本，比较文件大小及完整内容的 SHA-256。不使用 ETag 代替内容校验。缩略图、未引用文件、隐藏路径、符号链接、非普通文件及根目录外路径不清理；缺失和内容不匹配的副本保留。

在服务器项目根目录创建报告目录，并挂载到临时容器（需使用已包含清理工具的新镜像）：

```bash
mkdir -p cleanup-reports
docker compose run --rm --no-deps -v "$PWD/cleanup-reports:/reports" api python /app/tools/cleanup_local_images.py --report /reports/preview-$(date +%Y%m%d-%H%M%S).jsonl
```

报告逐项记录对象键、Bucket、地域、大小、可获得的校验摘要及结果，最后输出匹配数量、保留数量和可释放字节数。实际磁盘释放量可能不同于文件字节数。报告同名时拒绝覆盖；每条记录刷新保存。COS 或本地读取异常会记录错误并中止，不自动重试。

人工核对预览报告后，显式执行删除；删除阶段重新校验，不依赖旧报告：

```bash
docker compose run --rm --no-deps -v "$PWD/cleanup-reports:/reports" api python /app/tools/cleanup_local_images.py --delete --report /reports/delete-$(date +%Y%m%d-%H%M%S).jsonl
```

只有内容一致且校验期间本地文件未变化才删除本地文件，不删除空目录、不修改数据库、不删除 COS 对象。报告中的 deleted 表示删除调用已成功；异常中止前已删除的文件不会回滚。中途退出可能留下没有最终汇总的报告，应核对实际文件后再运行。

预览和正式删除均需读取 COS 全部候选文件内容，可能产生请求及流量费用。清理后不能直接切回本地模式回滚，需要先从 COS 或其他备份恢复文件。完成后恢复正常业务操作。

## 7. 数据持久化

### 7.1 图片

默认映射到项目根目录：

```text
./data/images
```

Linux 生产服务器建议在 `.env` 中设置绝对路径：

```text
IMAGE_DATA_PATH=/data/image-system
```

目录结构：

```text
员工ID/original/货号/原文件名
员工ID/processed/货号/原文件名
```

### 7.2 数据库和 Redis

MySQL 使用：

```text
qiye-image-system_mysql-data
```

Redis 使用：

```text
qiye-image-system_redis-data
```

可使用以下命令查看：

```text
docker volume ls
```

生产环境必须备份图片目录和 MySQL 数据。

## 8. 宝塔部署

### 8.1 安装环境

在宝塔软件商店安装 Docker 管理器。无需创建 Python 项目，也无需安装 Python 项目管理器。

将仓库放到例如：

```text
/www/wwwroot/qiyepic_system
```

在该目录创建 `.env`，然后启动：

```text
docker compose up -d
```

### 7.2 宝塔网站反向代理

Compose 默认将 Web 服务发布到：

```text
127.0.0.1 或服务器IP:1230
```

在宝塔创建普通 Nginx 网站，将域名反向代理到：

```text
http://127.0.0.1:1230
```

域名 HTTPS 证书继续由宝塔管理。

如果只允许本机宝塔 Nginx 访问，可将 `compose.yaml` 的端口映射改为：

```text
127.0.0.1:1230:80
```

### 7.3 防火墙

使用域名和宝塔 Nginx 代理时，不需要对公网开放 `1230`。只开放：

- 80；
- 443；
- 宝塔管理端口。

MySQL、Redis 和 FastAPI 均未在 Compose 中映射宿主机端口。

## 8. 镜像发布

应用镜像名称：

```text
qingmiaoai/qiyeimagesystem
```

构建：

```text
docker build -t qingmiaoai/qiyeimagesystem:latest .
```

推送：

```text
docker push qingmiaoai/qiyeimagesystem:latest
```

建议正式发布时同时使用版本标签，例如：

```text
docker tag qingmiaoai/qiyeimagesystem:latest qingmiaoai/qiyeimagesystem:0.1.0
docker push qingmiaoai/qiyeimagesystem:0.1.0
```

## 9. 图片清晰度处理

图片短边不足时：

1. 每阶段最多使用 2 倍 Lanczos 插值放大；
2. 最后一阶段精确缩放至目标尺寸；
3. 仅对放大结果应用轻度 `UnsharpMask` 锐化；
4. JPEG 和 WebP 使用 95 质量保存。

锐化参数：

```text
radius=1.2
percent=110
threshold=3
```

该方案用于减少普通插值造成的柔化，不能恢复原图中不存在的真实细节。
