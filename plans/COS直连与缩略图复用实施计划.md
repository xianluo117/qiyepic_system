# COS 直连与缩略图复用实施计划

## 1. 已确认范围

- 原图、处理图及历史版本通过现有应用链接跳转至 COS，图片正文不再经过应用服务器。
- 本地待同步文件仍由应用服务器提供；本地存储模式保持原样。
- 缩略图继续存放本地，后台处理时复用已经下载的原图生成。
- 保留旧图片缺少缩略图时按需生成的行为。
- 不增加 CDN、原图持久缓存、数据库迁移或新的存储后端。

## 2. 现状与收益

- 当前统一响应在 [`image_response()`](../backend/app/services/image_file_response.py:26) 中读取对象并转发。
- COS 读取见 [`CosStorage.open()`](../backend/app/storage/cos.py:23)，本地待办分流见 [`FallbackStorage.open()`](../backend/app/storage/fallback.py:118)。
- 后台处理下载原图见 [`_process_image()`](../backend/worker/tasks/image_tasks.py:87)；首次缩略图请求另行下载原图，见 [`read_public_thumbnail()`](../backend/app/api/routes/public_images.py:65)。
- 接口与后台任务当前共享图片目录，见 [`compose.yaml`](../compose.yaml:31)。

优化后，远端原图和处理图访问由 COS 直接向用户发送数据，应用服务器仅承担接口及跳转响应。COS 面向用户的下行仍然存在，不能理解为免流量。后台处理下载、缩略图输出、本地待同步文件输出仍消耗相应网络流量。

## 3. 实施设计

### 3.1 COS 临时地址

修改 [`cos.py`](../backend/app/storage/cos.py) 及必要的存储接口，在现有 COS SDK 上生成有期限的签名读取地址，不公开桶、不保存临时地址到数据库。

- 临时地址初始有效期采用固定 1 小时，不增加配置项。
- 签名包含返回内容类型、预览或附件下载方式，以及下载文件名；正确处理中文、空格等文件名。
- 应用对外链接保持长期稳定，每次访问重新生成临时地址。
- 地址生成在本地完成，不为生成地址下载对象正文。

### 3.2 统一响应分流

修改 [`fallback.py`](../backend/app/storage/fallback.py) 和 [`image_file_response.py`](../backend/app/services/image_file_response.py)。

| 对象状态 | 返回方式 |
|---|---|
| 纯本地存储 | 原有本地文件响应 |
| 本地待上传 | 原有本地临时流响应 |
| 待删除 | 文件不存在 |
| COS 已同步、无待办 | 临时跳转至 COS |
| 同步完成、待清理本地文件 | 临时跳转至 COS |

- 复用现有按对象锁与待办状态，不增加全局锁；不同图片请求不互相串行。
- 在现有对象锁覆盖下完成状态选择及本地流打开，避免同步清理与本地响应争用文件。
- 保留现有文件存在性探测及错误映射；远端探测只读取元信息，不读取正文。
- 使用临时跳转，跳转响应禁止缓存，不能沿用现有长时间不可变缓存头，避免浏览器长期保存过期签名地址。
- COS 最终图片响应的缓存语义与跳转响应分开处理，复用现有原图、版本图片的缓存意图。
- 公开预览、登录下载、历史版本下载均经过统一分流，不改变现有图片选择与版本解析规则。

### 3.3 前端与 COS 跨域

当前 [`GalleryView.vue`](../frontend/src/views/GalleryView.vue:365) 的普通下载和历史版本下载使用浏览器脚本读取二进制响应。跳转至 COS 后，这类请求需要 COS 跨域支持，不能只改后端就认为完成。

- 优先保留现有下载交互与下载命名，使用浏览器跟随跳转直接读取 COS 响应。
- 在 COS 桶中配置实际前端来源的跨域规则，允许读取方法及浏览器实际预检需要的请求头；不主动引入跨域凭据。
- 验收普通下载、历史版本下载、中文文件名及图片预览。不要在请求失败时改回服务器代理下载。
- 现有应用鉴权只用于应用请求，COS 请求由临时地址签名授权，不将应用令牌拼入 COS 地址。
- 复制链接、外部接口和 MCP 输出继续使用应用稳定链接，不输出即将到期的临时地址。
- 桶跨域配置是本方案下载交互正常工作的部署前提；若不能配置，需另行确认改为浏览器导航下载方案，不默默改变交互。

### 3.4 缩略图复用

修改 [`image_tasks.py`](../backend/worker/tasks/image_tasks.py) 并复用 [`thumbnail_service.py`](../backend/app/services/thumbnail_service.py)。

- 后台任务已取得原图后，在临时目录删除前生成缺失的本地缩略图，不再次从 COS 读取原图。
- 复用现有缩略图尺寸、质量、方向处理和原子写入，不改变展示效果。
- 已存在缩略图时直接复用，重新处理不重复生成原图缩略图。
- 缩略图是附属产物，不允许其生成失败把已经成功的主图处理标记为失败，也不因此重试整个主图处理任务。仅在该附属生成边界隔离异常，保留原有按需生成入口，不增加重试机制。
- 历史图片或缓存缺失时仍通过原缩略图接口按需生成，不批量回填。
- 后台任务与接口必须共享同一图片目录；当前容器部署无需新增挂载。
- 不承诺彻底消除所有重复下载：若缩略图请求早于后台生成完成，按需路径仍可能下载原图。本轮不新增跨任务原图缓存或复杂等待协调。

## 4. 故障与兼容边界

- 本地待同步文件继续可用，但普通远端对象没有新增本地副本。
- COS 在跳转前探测失败，沿用当前服务不可用反馈；跳转之后下载失败由 COS 或浏览器反馈，后端不自动接管。
- 只支持不改变语义的现有读取场景；外部 HTTP 客户端需要允许跟随跳转。
- 多用户预览不再通过后端传输大图，保留现有同步请求运行机制，不额外引入异步框架。

## 6. 验收清单

- 远端原图、处理图及历史版本请求返回临时跳转；后端不打开远端对象正文流。
- 浏览器最终图片数据来自 COS，跳转响应不被长期缓存，重新访问稳定链接能取得新地址。
- 预览正常；普通及历史版本下载正常，文件名符合现有行为。
- 本地模式及本地待上传对象保持可读；同步完成后改走 COS；待删除对象不提供内容。
- 后台正常处理且首次缩略图访问发生在生成完成后，原图仅因处理读取一次，缩略图访问不新增 COS 原图读取。
- 已有缩略图直接复用，旧图片缺失缩略图仍能按需生成。
- 缩略图生成失败不影响主图处理结果；不同图片任务继续独立执行。
- 不主动新增永久测试工程；若实施中创建临时回归代码，通过后删除，不删除原有测试。
