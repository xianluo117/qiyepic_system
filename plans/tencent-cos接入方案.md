# 腾讯云 COS 接入方案

## 一、已确认范围

- 环境变量选择本地或 COS，每次部署只使用一种后端，默认本地。
- 原图、当前处理图、全部保留的历史版本存入 COS。
- 全部历史有效图片一次性迁移，保持原存储键不变。
- 外部始终使用现有图床 URL，由图床后端流式中转 COS 内容，不重定向、不返回 COS URL。
- 缩略图保留本地生成和缓存。
- 不增加控制台配置、浏览器直传、CDN、双写、本地回退或数据库存储后端字段。

## 二、现状与改造边界

| 位置 | 现状与改造内容 |
| --- | --- |
| [`base.py`](../backend/app/storage/base.py) | 当前接口要求本地路径；拆开对象读写和处理工作目录，不让 COS 伪装成本地路径 |
| [`local.py`](../backend/app/storage/local.py) | 保留本地实现，路径键生成规则提到共用层 |
| [`images.py`](../backend/app/api/routes/images.py) | 上传、下载、版本下载和删除改用统一存储入口 |
| [`public_images.py`](../backend/app/api/routes/public_images.py) | 保持路由、版本解析及缓存规则，替换内容获取方式 |
| [`image_tasks.py`](../backend/worker/tasks/image_tasks.py) | COS 原图落临时目录处理，结果上传后才写入成功版本 |
| [`image_reprocessing.py`](../backend/app/services/image_reprocessing.py) | 对象清理改用存储接口；本地中间文件清理与对象删除分开 |
| [`thumbnail_service.py`](../backend/app/services/thumbnail_service.py) | 保留现有尺寸、白底和编码逻辑，缓存命中后不下载 COS 原图 |
| [`integration_images.py`](../backend/app/services/integration_images.py) | 图片链接生成规则保持不变 |

数据库已经保存相对存储键，参见 [`image.py`](../backend/app/models/image.py) 与 [`image_version.py`](../backend/app/models/image_version.py)。无需表结构迁移，前端和 MCP 返回结构保持不变。

## 三、存储与配置

### 3.1 最小模块划分

- 新增 [`cos.py`](../backend/app/storage/cos.py)：腾讯云 COS 适配器。
- 新增 [`factory.py`](../backend/app/storage/factory.py)：根据环境变量创建本地或 COS 存储实例，供 API 和 worker 共用。
- 对象接口覆盖保存、读取流、存在性、删除、大小查询和下载到指定路径；保存不再要求返回本地路径。
- 路径键生成规则保持现有员工、类型、货号、文件名结构。
- 本地路径访问仅限本地实现及本地处理分支，不作为 COS 的通用接口。

使用腾讯云官方 Python SDK，新增依赖同步写入 [`requirements.txt`](../backend/requirements.txt) 与 [`pyproject.toml`](../backend/pyproject.toml)。参考[官方入门文档](https://www.tencentcloud.com/document/product/436/12269)和[流式下载文档](https://cloud.tencent.com/document/product/436/65821)。采用简单上传、下载和删除接口，不新增自动重试或断点续传机制。

### 3.2 环境变量

| 配置 | 用途 |
| --- | --- |
| STORAGE_BACKEND | local 或 cos，默认 local |
| COS_SECRET_ID | 腾讯云 SecretId |
| COS_SECRET_KEY | 腾讯云 SecretKey |
| COS_REGION | Bucket 所在地域，如 ap-guangzhou |
| COS_BUCKET | 包含 APPID 的完整 Bucket 名称 |

不增加前缀、超时或独立临时目录配置项；对象键直接沿用数据库值，任务临时目录使用系统临时目录。

同步调整 [`config.py`](../backend/app/core/config.py)、[`.env.example`](../.env.example) 和 [`compose.yaml`](../compose.yaml)。API 和 worker 必须使用同一套配置；环境变量切换后重启两个服务。保留现有图片目录挂载作为本地模式数据目录及缩略图缓存目录。

## 四、运行链路

### 4.1 上传与处理

1. 上传保持现有图片检查、同名限制和响应结构，通过统一存储入口保存原图。
2. 原图保存完成后沿用现有数据库提交和 Celery 调度流程。
3. 本地模式保持现有处理路径；COS 模式为每个任务创建独立临时目录，下载原图并调用现有图片处理器。
4. 处理结果上传 COS 成功后，才写入版本、更新当前处理键和成功状态。
5. 临时目录在任务退出时释放，不依赖 API 与 worker 共享临时文件。
6. 过期版本删除、上传失败清理及重新处理清理改用当前存储后端，沿用现有失败状态反馈，不新增恢复流程。

图片处理算法保持在 [`processor.py`](../backend/app/processing/processor.py)，不改裁剪、缩放、压缩与版本保留规则。

### 4.2 下载与公开访问

统一内容响应逻辑放入新增的 [`image_file_response.py`](../backend/app/services/image_file_response.py)：

- 本地模式继续使用本地文件响应。
- COS 模式服务端打开对象流，按固定大小的二进制块中转，避免整张图片一次性加载到内存，也不先落完整缓存文件。
- 保留现有公开内联展示、认证下载附件文件名、内容类型及各路由缓存策略。
- 对象不存在继续返回现有图片不存在反馈；其他 COS 错误保留原始异常，不静默退回本地。
- 响应结束、读取异常或客户端断开时关闭上游流，避免占用连接。
- 不原样转发 COS 地址或全部响应头，不返回重定向。

并发方式：沿用现有同步 API 在线程池执行，COS SDK 调用及同步分块迭代不放进异步事件循环直接执行。CPU 图片处理仍由 Celery 独立任务承担，不阻塞 API；各任务使用独立临时目录，无全局串行锁。

图床依然承担所有未命中客户端缓存的图片流量；COS 到图床、图床到客户端两段链路均产生带宽消耗。此次接入用于对象持久化，不等于绕过图床服务器带宽。

### 4.3 缩略图

1. 沿用数据库图片记录检查。
2. 本地缩略图命中时直接返回，不读取 COS 原图。
3. 缓存未命中时，COS 模式下载原图到请求独立临时目录，交给现有缩略图服务生成缓存，随后删除临时原图。
4. 继续沿用现有唯一临时文件和替换缓存方式，允许并发首次访问，不新增分布式锁。
5. 保持现有缓存位置、输出效果及删除行为。

### 4.4 删除

沿用现有业务删除顺序，将原图、当前处理图、历史版本删除操作统一转发当前存储后端，本地缩略图仍由缩略图服务删除。不增加跨数据库与 COS 的事务补偿机制。

## 五、历史迁移与切换

新增一次性工具 [`migrate_images_to_cos.py`](../tools/migrate_images_to_cos.py)，显式读取本地图片根目录及 COS 环境配置，不受当前默认本地模式限制。

迁移范围为数据库引用的全部原图、当前处理图与历史版本对象，合并相同对象键后逐个上传。缩略图、处理中间文件和无数据库引用的残留文件不作为历史有效图片迁移。

### 操作顺序

1. 先部署支持两种后端的程序，保持本地模式。
2. 暂停上传、重新处理和删除，等待已有处理队列排空，再停止 worker，避免迁移期间源文件变化。使用维护操作完成，不新增业务维护开关。
3. 迁移工具分批读取数据库引用，从本地读取文件并按原键上传 COS，不修改数据库。
4. 工具输出成功上传数量及字节数；本地文件缺失时跳过并继续，结束时打印缺失数量和完整对象键清单，不删除数据库记录。COS 上传失败仍直接暴露错误。再次运行按相同键覆盖上传，不新增断点记录、重复检查或冲突策略。
5. 迁移命令成功完成后，将 API 和 worker 一起切换为 COS 并重启，恢复业务写入。
6. 通过旧链接验证历史原图、处理图和历史版本，再验证新增上传及处理。
7. 不自动删除本地历史目录；是否清理由用户后续决定。

切换前可随时保持本地模式。切换后如果已有新增或删除，不能只改回本地模式视作完整回滚；两端数据已可能不同。本次不做双写或反向迁移工具。

## 七、验收与前提

### 功能验收

- 本地模式上传、处理、下载、公开 URL、重新处理、版本保留和删除保持原行为。
- COS 模式原图和版本对象成功入桶，数据库对象键保持原结构。
- 所有对外图片链接保持图床域名，无重定向和 COS URL。
- 原图内容与迁移前一致，版本修订参数与原有缓存语义保持有效。
- 认证下载保留附件文件名；公开图片仍可直接展示。
- 缩略图未命中时从 COS 生成，命中时不重复下载原图；并发请求可正常返回。
- 删除图片及过期版本时删除对应 COS 对象，并清理本地缩略图。
- 图床中转使用分块读取，任务独立运行，不占用异步事件循环执行阻塞 SDK。
- 迁移完成后，原有数据库及旧链接无需改写即可使用。

### 开始实施所需环境

准备可供当前程序读写的 Bucket、地域、SecretId 和 SecretKey，并由用户填写环境变量，无需在对话中提供密钥。图床 API、worker 均需可访问 COS；实际迁移和云端验收依赖用户提供的运行环境。

本方案只规划，不执行迁移、不修改业务代码、不自动启动任何前端构建命令。
